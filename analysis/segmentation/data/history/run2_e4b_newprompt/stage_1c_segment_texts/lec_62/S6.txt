[62/63] We know what a function is, typically, in a programming environment.
[62/64] So, once we define a function, we can use it whenever it is needed.
[62/65] The function will probably require some inputs or parameters in most cases.
[62/66] Sometimes they may not require any parameters, which are given to the function each time it is called, just like in any other programming environment.
[62/67] The Start function is an example.
[62/68] We have already seen it where the script starts running.
[62/69] However, we can also define our own functions.
[62/70] So, there are some prebuilt functions which are critical, which we need to use to make our script work.
[62/71] But there are also user-defined functions, which are typically part of any good script.
[62/72] There is a class of functions called event functions.
[62/73] These are activated by Unity in response to events that occur during gameplay.
[62/74] Some such common and important events are regular update events, such as the Update function, FixedUpdate function, and LateUpdate function.
[62/75] Then initialization events, such as Start and Awake; GUI events, such as OnGUI, OnMouseOver, and OnMouseDown.
[62/76] Physics events, such as OnCollisionEnter, OnCollisionStay, and OnCollisionExit, relate to when contact is made or broken.
[62/77] Similarly, other physics-related events can be OnTriggerEnter, OnTriggerStay, and OnTriggerExit.
[62/78] These are called when a collider is configured as a trigger.
