There is another way of saving it. That is, you can use the file menu option. Under this, you can use the save option. Then a dialog appears. You provide the details and you can save it. The answer lies in what we have just discussed, that is, these options are given to cater to different groups of users. Typically, when we are talking about novice users, they are basically the users who are using it for the first time.
For novice users, remembering hotkey combinations is generally considered difficult. So, they have to recall the knowledge. So, this menu option is given through which they can save it.
Of course, that is, It takes a longer time as compared to the hotkey combination, but for novice users, it is suitable. For intermittent or expert users who have used the system for a longer duration or multiple times, the hotkey combination may provide a better alternative as compared to the menu option. Particularly for expert users, for them the hotkey combination is always preferable as compared to the menu option. Now, one thing to note here is that when we are talking about expert users, they are not really technology experts, rather they are experts in using the system.

This brings us to the important concept of usability. Usability tells us how good the system is from the point of view of the user. So, essentially what we require is an explicit measure a measure to judge our design if we have taken care of the human factors. Now, this measure is called usability.
So, essentially it is a measure of the goodness of a system from the point of view of the user. Like before, let us go through the definition of usability. So, we will be following the ISO, International Standards Organization definition. It is the ISO 9241-210-2009 standard definition of usability, which is the extent to which a product can be used by specified users to achieve specified goals. So, used by specified users to achieve specified goals.
with effectiveness, efficiency, and satisfaction in a specified context of use. So, these are crucial considerations when we are talking about building a usable product, a product that is supposed to have taken into account users' needs and expectations. So, there are three crucial aspects in this definition. First is the product is meant to be used by a specified group of users. In other words, a usable product need not be designed for all.
So, when we start building our system, we should not try to think that our system is going to be used by anybody and everybody whoever comes. Instead, we should try to clearly identify the target user groups and accordingly try to build a usable system. Only then is it likely to be able to satisfy the users. Otherwise, if we start by assuming that it is meant for everybody, then most likely it will not be able to satisfy all possible users. So, we should always try to identify the specified group of users for whom we are building the system.
The product should allow the users to achieve a specified set of goals. So, we should not try to let the user do anything. Instead, we should allow the users to perform specified tasks to achieve specified goals. So putting every conceivable feature in a product does not necessarily lead to a usable product. That is another crucial aspect of the definition.
That is, when we are building a system, we should not assume that it must be feature-rich. It should have all possible conceivable features as part of the package. In that case, users are most likely to get confused. They have specified goals. They have specified goals.
They have specified needs and expectations. So only those features we should carefully identify and support in our design. Thirdly, the product should be designed for a specified context of use. Clearly, a usable product need not be so for all usage scenarios. So, even if we are assuming that we have specified the users and we have specified features catering to the needs and expectations of the users.
Still, we should not expect that even for those users it should be usable for all usage contexts. Ideally, the usability is restricted to a specified context of use. So, these three are very crucial: we should not try to build systems for everybody, and accordingly we should not try to make it as feature-rich as possible, and thirdly we should not expect The specified users to be happy always whenever they are using the system. Instead, it is supposed to make them satisfied when they are using it in a specified context of use.
Also, the ISO definition of usability reveals three measures. Usability, as we have started with, is a measure of how good a system is from the point of view of the user. So there are three crucial aspects, but along with that, there are three measures of usability. What are those measures? First is effectiveness, how effective the product is; efficiency, how efficient it is; and satisfaction, whether the user is satisfied.
So, effectiveness essentially refers to whether the user is able to do whatever they want to do. Efficiency refers to how fast the user can do what they want to do, and satisfaction refers to how satisfied the user is when they are using the system. So, these are broadly the metrics to measure usability.
