A coroutine allows a developer to spread tasks across several frames. This is nothing but a method that can pause execution and return control to Unity, but then continue where it left off on the following frame.
It is important to note that coroutines are not threads. They are not designed to behave like threads. Synchronous operations that run within a coroutine still execute on the main thread. So, there are no individual threads spawned out of the execution of the coroutines. For example, consider the task of gradually reducing an object's opacity value until it becomes invisible.

So, then over a period of time we can perceive the change in the opacity value and then correspondingly how the object is disappearing gradually over a period of time.
