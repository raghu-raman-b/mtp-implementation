Part II · The pipeline

Stage by stage

Each stage below gives what it does and why, its inputs and outputs, the command, the model and config, how long it took on the VR course, its prompt in full (click to open), a real input and output from lecture 30, and the changes made to it with the reason. All paths are under pipeline/; outputs under pipeline/output/nptel_vr/.

Common to every model stage
  • One client (scripts/llm/) for vLLM and llama.cpp, both through the OpenAI chat API. A config file (configs/*.json) sets the engine, model, sampling, thinking budget and server flags.
  • Answers are constrained to a JSON schema built by code, then parsed and checked. A failed check is sent back to the model with the problems listed (“Your answer has these problems: … Answer again in the same format, fixing these problems and changing nothing else.”), up to the config's retries. When every attempt fails, the attempt with the fewest problems is kept and marked unresolved (decision D12).
  • Every answer is cached in the stage's llm/cache.jsonl under a hash of the request (engine, model path and request body: prompt, schema, sampling, token limits). The same request is never sent twice; a prompt change reruns only the requests it changes. Every call is logged in llm/calls.jsonl (tokens, time, errors).
  • All requests of a stage go out at once (generate_many), and the server batches them: up to 128 at a time on the 96 GB GPU. Qwen 3.8 27B FP8 on vLLM produced about 1,650–1,850 output tokens per second with the batch full, and about 45 tokens per second for a single request (ec2_sync/queue/logs/ (local)).
  • Prompts are plain text files in prompts/ with {placeholders}. Most begin with the course block (prompts/course_meta.txt: the course outline and syllabus from course.json), so the engine reuses its cached prefix across calls.

0a

Preprocess: subtitles to timed sentences

code

Every later stage works with sentences: the segmenter reads them, segments are runs of them, facts cite them, and their times turn a citation into a moment of the video. Stage 0a joins all subtitle cues of a lecture into one stream, splits it at sentence ends and gives each sentence an ID and the times of the cues it came from.

The rule. A sentence ends at ., ? or ! (with any closing quote or bracket), followed by a space and a capital letter, a digit or an opening quote. Dr., Prof., e.g., i.e., vs., Fig., Eq. are not ends; MR. (mixed reality) is. A lowercase word after a full stop does not start a sentence: in the VR course that full stop is the mistake (286 times, “…technologies. which, …”). A sentence keeps an exact time only where it starts or ends at a cue's edge; otherwise that side is null, and no time is made up.

Changes and why

  • Rule-based splitter, kept after a comparison with pySBD on six courses: it finds 94–99.7% of pySBD's boundaries, and where they disagree ours was right in the samples read (pySBD splits “…this is the result is n by ‖ n.”). analysis/preprocessing/report.md.
  • MIT caption conventions (speaker labels, sound tags, the OCW licence notice) handled so the same code runs on five other courses; the VR output stayed byte-identical.
  • Times of a segment boundary inside a cue, three versions: forward from the nearest exact time (VR median error 1.4 s, max 14.4 s), both sides from the nearest exact sentence times (0.9 / 7.4 s), then both sides from the edges of the cue the boundary is in (0.4 / 5.8 s; in Programming in C the max fell from 264 s to 12 s). Only segment boundaries are estimated (in stage 1b); sentences keep null. Example, lecture 57 sentence 206, 4 words into a 33-word cue from 2129.808 s to 2146.991 s: forward 2131.49 s, backward 2134.82 s, estimate 2133.16 s.
1a–1c

Segmentation: one sub-goal per segment

Qwen 3.8 27Bcode checks

A learner should be able to watch a segment on its own and come away able to do one thing. Stage 1a asks the model, once per lecture, where each sub-goal starts and what it is. Stage 1b checks the answer in code and, when a check fails, sends it back with the problem. Code never merges, splits or moves a cut itself. Stage 1c writes one text file per segment for the next stages.

The prompts

The 1a prompt is the task first, then the course block, the lecture's title, the definitions (sub-goal, segment, what is not a sub-goal, where to cut, standing alone), a working method, the answer format and the transcript numbered from [1]. The answer is {"reasoning", "segments": [{"start", "subgoal"}]}: the reasoning comes first so the model commits to why, and 1b sends it back in a retry. The two retry prompts are appended to the conversation: the 1a prompt, the model's last answer, then the retry. The model is told which segments “look too small” or “look too big”, never the bounds or the durations, and it may keep a segment it judges right.

  • A small model ignores the finer rules; a capable one applies them literally. The 4B labelled greetings as sub-goals and cut list items apart; the 12B followed “stand alone” into 28-minute segments (“Therefore, Segment 2 and 3 must be merged.”). The fix was rules it cannot over-apply: “Connectives are not dependencies. … Never merge segments or move a cut because of a connective.”
  • Length is checked in code, not prompted. A 6–15 minute rule in the prompt was considered and dropped: run 1's median segment was 2.4 minutes (557 segments), so code would have done the segmenting. Two retry wordings were tested on 8 lectures; the one with a direction (“see whether small ones together make a more meaningful sub-goal”) kept the lecturer's structure better than the bare “check them”.
  • Run to run, about three quarters of the cuts reproduce: boundary F1 0.75 between seeds of the same pipeline, WindowDiff 0.15. The disagreement is in lectures that enumerate items (lecture 8: six qualities of immersion). Qwen 27B against Gemma 12B: F1 0.76, about the same as Gemma against itself. Later stages should not treat a boundary as exact.
  • A dependency judge was tried and left out (prompts/segmentation_judge.txt, below): no false alarm on 6 controls, but 2 of 10 borderline segments flipped between two runs. Decision of 2026-11-11: not part of the pipeline.
