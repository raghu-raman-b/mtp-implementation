QA

Question answering: a tool agent over the layer

Gemma 4 12Bquery embedder

A learner's question goes to a small model with five tools over knowledge/. It may only answer from what the tools return, and must put the IDs it used in square brackets after each claim. Code then turns each ID into “(lecture N, m:ss)”, drops any ID no tool returned, and reads the model's last line, COVERED: yes / partly / no.

In
the question, optionally the lecture being watched; knowledge/ (or $QA_OUTPUT/<course>/knowledge/)
Out
{"answer", "citations": [{"fact", "lecture", "segment", "start", "end", "text"}], "steps", "covered"}; logs in output/<course>/qa/answers.jsonl and llm_calls.jsonl (gitignored)

Seconds; analysis/qa/STATE.md and the bench files. The vLLM row is computed from bench_vllm_shipped.jsonl.

  • Where the time went: thinking before the final answer (1,400–2,400 characters, 7–14 s), not the tools (0–0.9 s). Later rounds are now sent with enable_thinking: false; llama.cpp honours it per request and keeps its KV reuse (ebcc593).
  • Early exit. When every tool result so far found nothing close (ToolResult.found false), the next round must answer (“not covered” answers took about 20 s before; now about 4.4 s).
  • Thinking off everywhere was faster and wrong. Without thinking in round 0 the model answered a question the course does teach (B17, statistical tests, lecture 46) with “the course does not cover this”, without a search. Forcing a tool call did not work on llama.cpp: tool_choice: "required" made the model write its answer and run to max_tokens (3+ minutes), and a named function was ignored. On vLLM the forced variant had median 3.7 s but answered B17 without a search too (04a797a). Not shipped; the switches are qa.answer.ROUND0_THINK and ROUND0_TOOL_CHOICE.
  • Calibrated “no close match”. The cut-off was a guess (0.4). On 80 labelled queries (analysis/qa/calibration_queries.json) in-course scores run 0.63–0.86 and out-of-course 0.21–0.72 (AUC 0.989); 0.55 flags 27 of 39 out-of-course queries and none in-course (0.4 flagged 18).
  • Prerequisites ranked by use. Lists held odd items (“HMDs: displays from the 1950s” before lecture 16) because the graph links lectures on any single mention and the tool listed concepts in ID order. Now ranked by uses in the lecture.
  • Citations tidied: a time the model wrote before a citation is removed (the label carries the time); repeated labels in one line are written once; a list whose items share one label gets it once (90ffe5e). A tool's name written as a citation (“[lecture_dependencies]”) is removed (c0a0c8d).
  • Streaming (qa.answer_stream, efa7e21): time to the first draft median 3.2 s against 3.2–6.6 s to the whole answer.
Viewer

The viewer

standard-library Python + one page
As of 2026-11-18 · being redesigned

The viewer is what a learner opens. This describes it as it is on main; its look is being redesigned by another agent. viewer/serve.py (standard library only) serves the page (index.html, app.js, style.css, vendored dagre for map layout), the layers through lean JSON routes, the videos with HTTP Range, and the question box. Every layer is optional: a lecture without knowledge/ shows its 1b segments and its 0a transcript.

Command
python viewer/serve.py nptel_vr [--port 8765] [--host 127.0.0.1] [--root DIR] [--media DIR] [--output DIR] [--activities NAME] [--qa-path DIR] [--warm] [--prefer-youtube] [--video-chunk-mb 4] [--video-pace 2], then open http://localhost:8765
Pages
#/ course home (goals, lectures by week); #/lecture/<key>[/<tab>] with tabs overview, concepts, map, before, activities; #/lecture/<key>/t/<sec> seeks the video; #/concept/C0042 a card; #/glossary; #/map (course map and concept explorer); #/review
Flags in the page
?dev=1 developer mode (IDs, counts, judge marks, hidden items; learners never see statistics); ?yt=1 / ?yt=0 prefer YouTube; the theme toggle
  • Glossary: only the 1,316 defined concepts; connecting concepts stay on maps and keep their cards, and come in the glossary route by name only, for the explorer's search. Search by name, alias or acronym (“HRTF”).
  • Hiding: judge-failed items by the per-kind rule above; activities marked unresolved show only in developer mode.
  • Concept maps: a key view of about 20 concepts by default and an “all N, by part” view; the course map shows lectures by week with prerequisite arcs (0965ba9).
  • Videos: local files with Range, or YouTube by the youtube_id in titles.tsv when a file is missing.

Speed work and why

The live demo of 2026-11-13 felt choppy: the page loaded the four big knowledge files (9.6 MB) on every visit, and the demo was to run through an SSH tunnel. The rework (analysis/viewer/perf.md): lean routes built once and gzip-compressed with ETags (a reload answers 304); static files versioned and cached for good; lectures loaded lazily with neighbours prefetched when idle; tabs and map views built once and kept; the glossary rendered in slices; video answered in 4 MB chunks and paced at twice its bitrate so a tunnel never queues minutes of video ahead of the page; answers streamed.
