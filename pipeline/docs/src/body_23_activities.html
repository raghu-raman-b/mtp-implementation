Activities: ten kinds, code checks, a judge, one rewrite

Stage 5 reads only the knowledge layer and writes what a learner does around each lecture. Every activity lists the facts and concepts it is built from, so every item can be checked against them and every answer linked to a moment of the video. A model writes only the kinds that need language; the others are code.

The writer prompts

Each prompt says what the learner will see (and what they will not: the facts), gives the rules with examples from another subject, and ends with a self-test the model runs before answering. The quiz prompt, for instance, asks it to “cover the options”, “compare lengths” and “argue for each wrong option as a learner would”.

Code checks: hard and soft

Every model answer is checked in code. A failure goes back to the model with the problem written out, as the next turn of the same conversation. The checks come in two classes (Fable's review, analysis/activities/review_prompts.md section 7):

  • Hard: an item that still has the problem after the last attempt is dropped. A cited fact number outside the list; a count out of range; quiz options not one right and three wrong, two the same, “all of the above”, a question not ending in “?”; an odd-one-out group of the wrong size or reused; put-in-order steps not 3–8; a clue containing its answer, over 15 words or the same as another clue.
  • Soft: retried, but an item that still fails is kept and flagged by name, and the judge decides. source_talk (“the segment”, “the facts state”, “according to the lecture”) for every kind; correct_longest (the right option over 1.2 times and 12 characters longer than every wrong one) and correct_longest_share, absolute_wrong for quizzes; text_repeats_points, point_long, text_length for recaps; order_cue; shared_word, length_tell; two_questions, reference_long; clue_list_place.
  • Fixes in code: options and clues lose a trailing full stop; odd-one-out items get a capital; final masking hides only the answer's own name and its plain forms.

The judge, the rewrite and the hiding rules

With --judge, one call per unit (a segment's quiz or recap, a lecture's puzzles, exercises, questions or clues) checks every item against named criteria, after the code checks. The judge sees what the writer saw, with the same fact numbers, and the items as the learner will see them (quiz options in their shuffled order). It must do a piece of work before deciding (the check field: for a quiz, the letters of every option the facts make correct, found before reading the key) and name the criteria an item fails. In doubt it fails an item on the criteria where a learner would be taught something wrong, and passes it on criteria of form.

With --judge-rewrite, a unit with a failed item gets one rewrite: the writer's conversation continues with prompts/activity_rewrite.txt, one line per failed item with the judge's criteria and reason; the code checks run again, then the judge once more. The rewrite is kept only when the judge fails strictly fewer of its items. Nothing is dropped on a verdict: what still fails is flagged judge_failed.

What a learner sees is decided by a per-kind rule in the viewer (HIDE_JUDGE_FAILED in viewer/serve.py, the coordinator's decision of 2026-11-17). In developer mode every failed item is shown and marked with its criteria.

Changes and why

The MVP's activity prompts (2026-11-13) were written in a hurry by Opus and never reviewed. Fable read the 63 lectures' outputs against their facts, counted each weakness with a rule that code could later apply, and rewrote the prompts and wrote the six judges (312cb6c, analysis/activities/review_prompts.md).

Rebuild: an order of work, a self-test, a soft check, a judge

“Write the correct option first, then build each wrong option to match it … At least one wrong option is as long as the correct one or longer.” Plus the correct_longest check with retry and the judge's no_giveaway criterion. See quiz 30/A9 above: four options of one shape.

The recap judge was too strict on wording. Its first run failed 969 recap items. Reading them, Fable found it failed paraphrases and dropped details that do not change what is true. Criteria 1 and 2 were rewritten to “judge the meaning, not the wording” (d730cd4) and the recaps judged again: 593 items failed. Over all kinds the judge's failures went from 1,465 to 1,086 (376 of the drop from the recap re-judgement, 3 from the odd-one-out rerun) (the counts are in the judge cache, activities/llm/cache.jsonl, keys judge1:recap:*, old and new).
