[61/S0/F0] The Unity developer environment is an implementation platform with an editor interface through which a developer can create, build, and deploy a system, and it provides support for building an XR experience.
[61/S0/F1] Render pipeline support is an important graphics support offered by Unity, providing support to implement the entire render pipeline—camera and view transform, lighting, meshes, materials, textures, shaders, and environment creation (world scene or world-coordinate-system scene creation, special environments such as skies, and different visual effects)—and also letting the user have customized control over individual pipeline stages.
[61/S0/F2] Unity provides three pre-built render pipelines, the built-in render pipeline, the Universal Render Pipeline (URP), and the High Definition Render Pipeline (HDRP), and a developer can also create a custom render pipeline using Unity's scriptable render pipeline application programming interfaces (APIs).
[61/S0/F3] The built-in render pipeline in Unity has limited options for customization, so a developer has to work with the options that are already provided.
[61/S0/F4] The Universal Render Pipeline (URP) in Unity is a quick and easy way to customize graphics and create optimized graphics across a wide range of platforms.
[61/S0/F5] The Universal Render Pipeline (URP) in Unity has many pipeline stages optimized by the pipeline implementation itself, and it takes care of pipeline-implementation optimization to some extent, so a developer need not manage those aspects and resource requirements are minimized.
[61/S0/F6] The High Definition Render Pipeline (HDRP) in Unity is a customizable pipeline specifically meant for creating cutting-edge, high-fidelity, photorealistic graphics.
[61/S0/F7] The High Definition Render Pipeline (HDRP) in Unity requires a good amount of resources and is typically meant for high-end platforms, such as high-end graphics workstations with good graphics processing unit (GPU) support.
[61/S1/F0] Unity's built-in render pipeline supports object definition by providing models, which are files containing data on the shape and appearance of three-dimensional (3D) objects and are essentially the object representation.
[61/S1/F1] A Unity model file can contain mesh, material, and texture data, and, if the object represents an animated character, it can also contain animation-related data.
[61/S1/F2] Unity supports more than 10 standard and proprietary model file formats, including the .fbx format, the .dae format, the .dxf format, and the .obj format, so models created in different formats can be imported into Unity and made to work.
[61/S1/F3] In Unity, three-dimensional (3D) meshes are the main graphics primitives, and Unity supports triangulated or quadrangulated polygonal meshes, meaning meshes whose polygons are triangles or quadrangles.
[61/S1/F4] In Unity's mesh rendering workflow, the mesh renderer takes geometry from the mesh filter and renders it at the position defined by the game object's transform component.
[61/S1/F5] In a Unity model file, materials describe the appearance of an object's surface by specifying how the surface should be rendered, including references to textures used, tiling information, color tints, and other information, whereas meshes describe the object's shape.
[61/S1/F6] In Unity, textures are bitmap images applied over a mesh surface as a way to assign colors to the surface, and they can represent many other aspects of a material's surface in addition to basic color, such as reflectivity and roughness.
[61/S2/F0] The Unity editor supports scene creation by transferring objects from local coordinates to world coordinates and by providing tools to create and modify environmental features such as landforms, vegetation, and the landscape.
[61/S2/F1] The Terrain Tools Preview package provides additional functionality on top of the built-in terrain features in the Unity editor.
[61/S2/F2] The Tree Editor is a Unity editor tool that lets developers design trees directly in the editor; the latest Unity version supports the SpeedTree toolkit instead of the Tree Editor, while earlier versions still provide the Tree Editor.
[61/S2/F3] A skybox in Unity is a sky background that a camera draws before it renders a frame; it is a cube with different textures on its faces to create the feel of a 360-degree environment, and Unity always renders the skybox at the back.
[61/S2/F4] Unity provides support for realistic lighting on game objects, allowing developers to specify the intensity, direction, and color of the light and to render real-time shadows using shadow mapping.
[61/S2/F5] In the Unity developer environment, visual effects can be applied to the camera, game objects, light sources, and other elements of the game.
[61/S2/F6] The halo effect is a visual effect that creates light areas around light sources, typically to give the impression of small dust particles in the air.
[61/S2/F7] The lens flare effect is a visual effect that simulates the effect of lights refracting inside a camera lens.
[61/S2/F8] The line renderer effect is a visual effect that takes an array of two or more points in 3D space and draws a straight line between those points, enabling anything from a simple straight line to a complex spiral to be drawn.
[61/S2/F9] View transformation, also called the viewing pipeline, is an important stage in the 3D graphics pipeline.
[61/S2/F10] Unity supports view transformation through its camera concept; after a developer sets up a camera, Unity performs the other calculations automatically.
[61/S2/F11] In Unity, a camera is created by adding a camera component to a game object.
[61/S3/F0] Unity does not implement the graphics pipeline itself but uses functions of native rendering libraries to implement the graphics pipeline, and Unity takes care of implementation concerns, so a developer does not need to manage the graphics pipeline implementation.
[61/S3/F1] The major native graphics libraries supported by Unity are DirectX, which is primarily in the Windows environment, Metal for Apple systems, Open Graphics Library (OpenGL), and Vulkan, and many other native graphics libraries are also supported.
[61/S3/F2] Depending on the availability of an application programming interface (API) on a particular platform, Unity can support the corresponding native graphics library.
[61/S3/F3] Unity's default graphics application programming interfaces (APIs) access native graphics library application programming interfaces (APIs).
[61/S3/F4] To use Unity's default graphics application programming interfaces (APIs), a developer opens the Player Settings editor interface using Edit Project Settings, selects the Player category, navigates to Other Settings, and checks the AutoGraphics application programming interface (API) option.
[61/S3/F5] When the AutoGraphics application programming interface (API) option for a platform is checked, the Unity player build includes a set of built-in graphics application programming interfaces and uses the appropriate one at runtime to produce the best-case scenario, so a developer does not need to decide which one to use or what is supported for a given platform.
[61/S3/F6] When the AutoGraphics application programming interface (API) option is not checked, Unity's editor uses the first graphics application programming interface (API) in the list, and if that one is not supported by the specific platform, Unity uses the next one in the AutoGraphics application programming interface (API) list until it finds an appropriate match.
[61/S4/F0] Unity's physics engine simulates physical laws in a project so that objects correctly accelerate and respond to collisions.
[61/S4/F1] The Unity physics engine includes rigid bodies, colliders, joints, physics articulation, and character controllers as components essential to give a realistic feeling.
[61/S4/F2] A rigid body in Unity is a concept and a property that, when attached to a game object, allows the game object to respond to gravity, so falling or bouncing from a surface appears realistic in accordance with everyday experience.
[61/S4/F3] The isKinematic property, used with a Unity rigid body, can remove the object from physics engine control and allow it to be moved kinematically from a script, so it does not automatically follow gravity, and the developer can choose whether the object follows gravity.
[61/S4/F4] A collider in Unity defines the shape of a game object for physical collisions, allows the developer to deal with the object's shape after it collides with another object, and includes types that are primitive colliders such as box collider, sphere collider, and capsule collider, or mesh collider, which is more processor-intensive but accurate.
[61/S4/F5] In Unity, static colliders can be added to a game object without a rigid body component to create floors, walls, and other motionless elements of a scene.
[61/S4/F6] In Unity, physics materials are used to configure the friction and bounce of a surface.
[61/S4/F7] A collider in Unity configured as a trigger using the isTrigger property does not behave as a solid object and simply allows other colliders to pass through.
[61/S4/F8] In Unity, a joint connects a rigid body to another rigid body or to a fixed point in space, can apply forces that move the rigid bodies, has limits that restrict that movement, and can be used to model the realistic movement of specific objects or characters such as a ball and socket joint like a hip or shoulder, any skeletal joint, doors, finger joints, or a piece of elastic.
[61/S4/F9] Physics articulation (articulation) in Unity is the overall movement of a structure or object comprising joints, and it provides realistic physics behavior that involves joints.
[61/S4/F10] In Unity, articulations can be configured via the articulation body class or the corresponding articulation body component, which provides inbuilt support that automatically implements joint constraints, so a developer does not need to control each individual joint to make a complex figure move realistically.
[61/S4/F11] The articulation body class in Unity represents articulation bodies as a logical tree in which each node is a joint and each parent-child relationship reflects mutually constrained relative motion, so the relations and relative movements of the joints define the overall articulation.
[61/S5/F0] Unity provides an animation system that supports importing animation clips and animations created within Unity, humanoid animation retargeting, a simplified workflow for aligning animation clips, convenient preview of animation clips, transitions and interactions between animation clips, management of complex interactions between animations with a visual programming tool, and animating different body parts with different logics.
[61/S5/F1] Humanoid animation retargeting in Unity is the ability to apply animations from one character model onto another.
[61/S5/F2] Although animation processing in Unity involves stages similar to the three-dimensional (3D) graphics pipeline stages, Unity lets a developer work directly with animations without implementing those pipeline stages or their computations.
[61/S5/F3] Unity provides support for the audio sense in immersive experiences through dedicated components for audio perception and playback: audio source, audio listener, and audio filters.
[61/S5/F4] The Unity audio source is the primary component attached to a game object to make it play a sound, and it allows an audio clip, which can be any standard audio file such as MP3 or WAV, to be played back when triggered through a mixer, code, or by default.
[61/S5/F5] The Unity audio listener is a component that listens to all audio playing in the scene and transfers it to the computer speakers; all heard audio is with respect to the audio listener's positioning, and by default only one audio listener should be in the scene attached to the camera.
[61/S5/F6] Unity audio filters are components that modify the output of an audio source or the intake of an audio listener to generate various sound effects, and each filter is provided as its own component.
