[32/S0/F0] User-centered design, also called user-centric design, human-centric design, or participatory design, is an approach that actively or passively involves users in the overall design lifecycle, including design and implementation, with the objective of designing application software products that are usable.
[32/S0/F1] The core design concern for user-centered software is designing usable systems that meet the needs and expectations of laypersons.
[32/S0/F2] The extended reality (XR) application software being developed is interactive software intended for laypersons, who may not know or need to know how the hardware or software works.
[32/S0/F3] Obtaining usable application software requires following a structured, step-by-step software development lifecycle rather than working in a haphazard or ad hoc manner.
[32/S0/F4] A software development lifecycle is a systematic, structured set of connected stages for developing and deploying software that comprehensively capture and represent the design and development activities needed to build the software.
[32/S0/F5] Software engineering can be used as a single term that represents the idea of a software development lifecycle, and engineering software means building the software in stages.
[32/S1/F0] A design space is the set of all possible designs, and when n distinct objects are placed on a screen without repetition, the typical size of the design space is n factorial, with the number of arrangements increasing if repetition is allowed.
[32/S1/F1] A calendar application has a fixed and large number of elements to be displayed, such as month names, dates, and possibly the year, so it has a very large design space.
[32/S1/F2] In a calendar application, many possible designs may be invalid because dates must be ordered in a particular way, but in most practical systems a reasonably significant number of valid design choices can remain, such as 10, 15, or 20.
[32/S1/F3] A software development life cycle (SDLC) is a systematic approach that helps identify the best valid design choice in terms of usability, because intuition may not lead to the single best solution for everyone.
[32/S2/F0] A software development lifecycle is a set of stages that should ideally be followed in a particular sequence.
[32/S2/F1] In interactive system design, users must be taken into account in every stage and involved as active or passive participants.
[32/S2/F2] A highly iterative software development lifecycle is required for a user-centric design approach to usable interactive systems and extended reality software, because including users' needs and expectations changes the stage sequence and creates loops where a developer may return to a previous stage instead of proceeding to the next stage.
[32/S2/F3] In an interactive system development lifecycle, iterations between stages are intended to account for user feedback, where user feedback means involving users in different ways, not only through feedback.
[32/S2/F4] The iterative software development lifecycle for interactive system development comprises feasibility study, requirement gathering, analysis, specification, a design-prototype-evaluate cycle consisting of design, prototyping, and early evaluation, code design, coding and implementation, code testing, empirical study or usability study, deployment and maintenance.
[32/S2/F5] The design-prototype-evaluate cycle in the iterative software development lifecycle for interactive system development has iterations between its design, prototyping, and early evaluation stages, and it also has an iteration to the requirement gathering stage.
[32/S3/F0] In the development of interactive systems, end users must be involved from the requirement-gathering stage onwards, along with the customer or client, whereas typical requirement analysis refers to the requirements of the client.
[32/S3/F1] Methods for gathering end user requirements in the requirement-gathering stage include contextual inquiry, ethnographic studies, and cultural probes.
[32/S3/F2] The design-prototype-evaluate loop refines early designs for interactive systems using user feedback through many iterations, in which a design is prototyped, evaluated to identify problems, and refined until not many significantly different problems are identified, after which the design is stabilized and the next stage can begin.
[32/S3/F3] The design-prototype-evaluate loop and each of its stages must be completed quickly so that many iterations can occur within a reasonable time, because otherwise the overall turnaround time will increase significantly.
[32/S3/F4] The design-prototype-evaluate loop includes the activities of interface design and interaction design, primarily designing the interface and interaction from the user's point of view based on user requirements, while code design is a separate later design activity.
[32/S4/F0] Coding and code testing in interactive system development are carried out in the traditional software engineering way, through code design, then coding and implementation, then code testing.
[32/S4/F1] In the coding stage, code testing can reveal issues that require returning to code design, creating an iteration; fewer iterations are preferred because code design is a highly skilled, costly process and late problems are costly to rewrite and test.
[32/S4/F2] The iterative software development life cycle has three evaluation points: early evaluation, which quickly evaluates interface and interaction design ideas with fewer resources and less time as part of the design-prototype-evaluate cycle; code testing, which evaluates the code as part of coding and implementation; and empirical study.
[32/S4/F3] Code testing tests the executability of code by ensuring that the code is bug-free and executes properly, but it does not establish whether the system is usable from the end user's point of view.
[32/S4/F4] The empirical study stage is a usability-testing stage that is required to ensure that an interactive system product conforms to usability through systematic testing with end users, which is a different activity from code testing.
[32/S4/F5] The empirical study stage differentiates interactive system development from other software development and is typically not part of other software development in which end users are not involved.
[32/S5/F0] In the iterative design of usable extended reality systems, the design-prototype-evaluate cycle is the only loop designed to be performed quickly, and other loops, such as the loop between requirement gathering and the design-prototype-evaluate cycle, the loop between code design, coding, and code testing, and the loop between the design-prototype-evaluate cycle and coding, implementation, and empirical studies, should not be frequent.
[32/S5/F1] Frequent loops other than the design-prototype-evaluate cycle, particularly the loop between code design, coding, and code testing and the loop between the design-prototype-evaluate cycle and coding, implementation, and empirical studies, significantly affect a project's overall outcome and turnaround time, escalate development cost in manpower, time, and resources, and may lead to project abandonment.
[32/S5/F2] When building usable extended reality systems, the development stages should be completed carefully so that the need to return to previous stages does not arise.
[32/S6/F0] In the interactive system development lifecycle (ISDLC), building interactive software is broadly similar to building regular software, and the differences are in the requirement gathering, design-prototype-evaluate, and empirical study stages.
[32/S6/F1] The book Human-Computer Interaction, User-Centric Computing for Design discusses the stages of interactive system development life cycles in more detail with respect to broader interactive system development concerns.
