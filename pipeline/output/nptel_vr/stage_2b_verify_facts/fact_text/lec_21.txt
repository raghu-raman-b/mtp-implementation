[21/S0/F0] Augmented Reality (AR) software tools can be categorized by developer skill, target application platform (desktop AR applications or mobile AR applications), or tracking technology (computer vision (CV)-based tracking or other sensors such as Global Positioning System (GPS) sensors).
[21/S0/F1] In a skill-based hierarchy, Augmented Reality (AR) software tools are arranged in four categories according to decreasing programming skill: low-level software libraries or frameworks, rapid prototyping tools, plugins for existing developer tools, and standalone AR authoring tools.
[21/S0/F2] The skill requirements for the four skill-based Augmented Reality (AR) software tool categories are: low-level software libraries or frameworks require strong programming or coding ability and understanding of how to call the library functions; rapid prototyping tools require some programming ability, lower than for low-level tools, and may require design prototyping skills; plugins require skill with the original developer tool with which the plugin is used; and standalone AR authoring tools assume no programming ability and can be used without any knowledge.
[21/S0/F3] Examples of Augmented Reality (AR) software tools for each skill-based category are: AR Toolkit, OSG Art, StudiersTube, and MXR Toolkit for low-level software libraries or frameworks; FLAR Manager and OpenFrameworks for rapid prototyping tools; AR media plugins, Vuforia, MetaIO Unity plugins, and Dart for plugins for existing developer tools; and BuildAR, MetaIO Creator, and Wikitude for standalone AR authoring tools.
[21/S1/F0] Low-level libraries and frameworks are the augmented reality (AR) software category that requires the maximum skill from the developer because they provide access to the core tracking and display functionality used to build an AR application.
[21/S1/F1] ARToolKit is one of the most widely adopted software libraries for developing augmented reality (AR) applications; it is written in C and supports platforms such as Windows, Linux, and macOS.
[21/S1/F2] ARToolKit provides marker-based tracking in its open-source version, while its commercial version, available from ARToolWorks, also supports tracking natural features on an arbitrary image using computer vision techniques.
[21/S1/F3] ARToolKit is primarily a tracking-support library: it provides functions that enable a developer to perform tracking and then carry out a related activity.
[21/S1/F4] ARToolKit provides only low-level OpenGL-based rendering support, with very primitive rendering and no built-in support for interaction techniques or complex realistic graphics, so using it alone yields a rudimentary system in which the developer must write interaction from scratch, making a complete realistic augmented reality (AR) application difficult and time-consuming.
[21/S1/F5] Many standard augmented reality (AR) toolkits or low-level libraries primarily provide tracking support but lack the features needed for realistic rendering of digital content over the real-world view and for interaction support.
[21/S1/F6] To overcome the limitations of ARToolKit or other tracking-focused low-level libraries, a framework for augmented reality (AR) system development can be created by combining multiple libraries, especially libraries that provide interaction and realistic graphics support.
[21/S1/F7] A scene graph is a node-based graph, essentially a tree of nodes and links, that represents a computer graphics scene, allowing selective work with nodes to manipulate the scene, create realistic effects, and support interaction, thereby providing a way to manage the functionality of a complex graphics application.
[21/S1/F8] Scene graph-based representations support operations that are part of a three-dimensional (3D) graphics pipeline, including sorting objects according to visibility (visible surface detection), removing objects outside the camera field of view (clipping), state management, and higher-level abstractions of functionality.
[21/S1/F9] When ARToolKit is combined with a scene graph library, the scene graph library can take care of low-level object rendering, so the developer can focus on interaction between virtual objects while ARToolKit remains responsible for tracking.
[21/S1/F10] Open Scene Graph (OSG) is an open-source scene graph library, Vulkan Scene Graph (VSG) is an open-source successor of OSG, and both are widely used.
[21/S1/F11] Open Scene Graph (OSG) and similar scene-graph libraries are written in C++ and are built on top of OpenGL, which accesses lower-level hardware.
[21/S1/F12] Open Scene Graph (OSG) supports a large number of plugins for additional functionality such as model loading, shadow rendering, and physics, which are primarily relevant for virtual reality (VR) and partly relevant for augmented reality (AR).
[21/S1/F13] In an augmented reality (AR) example in which a phone detects a marker on a table and a three-dimensional (3D) cow object appears on the screen, the operation involves tracking, which recognizes the marker and its position, and three-dimensional (3D) registration, which creates and renders the cow at that position.
[21/S1/F14] In the marker-cow augmented reality (AR) example, combining ARToolKit with Open Scene Graph (OSG) or Vulkan Scene Graph (VSG) can perform the operations: ARToolKit handles tracking and three-dimensional (3D) registration, while OSG handles creation of the AR scene with the rendered cow.
[21/S1/F15] In a scene-graph representation of the marker-cow augmented reality (AR) example, the whole activity is represented as a node graph containing nodes for video input, tracking, a root node, a virtual camera whose parameters can be manipulated, projection, other related concepts, the three-dimensional (3D) object, and transformations represented as a single node or individual nodes; video input comes from the input device, tracking uses device sensors such as a camera, and graphics-rendering nodes include transformation, three-dimensional (3D) object representation, and orthographic projection, making the scene easier to visualize and manipulate to create the desired effect.
[21/S1/F16] Examples of frameworks that combine tracking and rendering libraries include the Open Scene Graph (OSG) ART 3 library, which links ARToolKit for tracking support with OSG for real-time rendering features; Goblin XNA, which combines the ART tag tracking library with the Microsoft XNA game platform; and Metaio SDK plus OSG, in which the Metaio SDK provides augmented reality (AR) tracking technologies and OSG provides rendering support.
[21/S1/F17] Mobile-specific augmented reality (AR) frameworks include ARToolKit for mobile, DroidAR, and Vuforia; DroidAR uses other sensors for tracking support, while Vuforia uses computer vision for tracking support.
[21/S1/F18] ARToolKit for mobile is a version of ARToolKit available for mobile platforms including iOS and Android, integrated with Open Scene Graph (OSG) but developed for mobile.
[21/S2/F0] Low-level augmented reality (AR) libraries and frameworks provide maximum development flexibility, but implementing an AR application with them requires knowing the library or framework and writing programs, so it is time-consuming and requires significant programming skill.
[21/S2/F1] Rapid prototyping and development tools are used to visualize an augmented reality (AR) idea with simple means before major development and show it to end users or clients, so an unsuitable idea does not require further coding.
[21/S2/F2] Adobe Flash is a popular authoring tool for creating prototypes with multimedia content for web and desktop platforms and can be used, through augmented reality (AR) plugins such as FLAR Toolkit or Flash AR Manager (FLAR Manager), to prototype desktop and mobile augmented reality experiences.
[21/S2/F3] FLAR Toolkit is a version of the augmented reality (AR) Toolkit ported to Adobe Flash and allows an AR experience to be run from within a web browser.
[21/S2/F4] FLAR Toolkit lets a user, with a few lines of code, activate a camera, track augmented reality (AR) markers in the camera view, and load and overlay virtual content onto the tracked image for three-dimensional (3D) registering.
[21/S2/F5] FLAR Toolkit makes it possible for anyone with a Flash-enabled web browser and a camera connected to a computer to have or develop an augmented reality (AR) experience with minimal effort because the required tracking and overlay activities can be done with a few lines of code.
[21/S2/F6] Flash augmented reality (AR) Manager (FLAR Manager) is a framework that combines various augmented reality tracking and graphics libraries, primarily for prototyping.
[21/S2/F7] In Flash augmented reality Manager (FLAR Manager), an augmented reality tracking library such as FLAR Toolkit or FLAR Tracker can be combined with a three-dimensional (3D) graphics library such as Alternative 3D, Away 3D, Away 3D Lite, Paper Vision 3D, or Sandy 3D, and such combinations are used primarily for prototyping rather than full-fledged development.
[21/S2/F8] Non-Flash-based authoring tools for augmented reality prototyping exist, but they may be less popular than Flash-based tools because Flash-based tools have greater market penetration.
