[38/S0/F0] The interactive system development lifecycle has two design stages: the design stage in the design-prototype-evaluate cycle and code design.
[38/S0/F1] In the interactive system development lifecycle, code design is the same as code design in any other non-interactive software development.
[38/S1/F0] Designing an immersive experience involves the design-prototype-evaluation cycle in order to incorporate user requirements.
[38/S1/F1] Interface and interaction design involves two issues: where or how to start the design process and how to express a design so that it can be brainstormed and refined, which means having a design language.
[38/S1/F2] Interface and interaction design requires creativity and imagination, and the design process can be started from creativity aided by intuition, expertise, experience, or domain knowledge, and/or from guidelines, often called checklists, heuristics, or thumb rules.
[38/S1/F3] Some design guidelines are generic, small in number, and cover broad high-level aspects of interactive systems; examples are Shneiderman's eight golden rules and Donald Norman's seven principles, both primarily intended for graphical user interfaces (GUIs) but applicable to other domains, with Norman's seven principles developed in the 1980s.
[38/S1/F4] Other design guidelines are more detailed and specific, generally large in number, and cover the micro details of a particular system or product; for example, Apple's human interface guidelines were originally developed for Apple's user interfaces.
[38/S1/F5] A design language is a specification of design, and there can be different languages for specifying a design; the language used to specify interface design is generally different from the language used to specify code design.
[38/S1/F6] A prototype can be considered a language for expressing interface and interaction design ideas.
[38/S2/F0] The virtual reality (VR)-specific guidelines for avoiding or minimizing cyber sickness are specific design guidelines that are typically applicable to virtual reality or immersive systems where immersion is very important, but may not be specifically applicable to augmented reality (AR) systems because augmented reality immersion differs from virtual reality immersion.
[38/S2/F1] Generic design guidelines are guidelines applicable to any interactive system, including extended reality (XR) systems, although they are mostly, not fully, applicable to extended reality systems.
[38/S2/F2] Ben Shneiderman's Eight Golden Rules are a set of eight generic design rules originally developed in 1986 primarily for graphical user interfaces (GUIs), and can be partly or fully applicable to other types of interfaces, including extended reality (XR) systems.
[38/S3/F0] Shneiderman's first golden rule of system and interface design is to strive for consistency.
[38/S3/F1] The consistency required by Shneiderman's first golden rule has two types: internal consistency and external or environmental consistency.
[38/S3/F2] Internal consistency in system design means using the same elements and interactions for the same task across different parts of a design and different usage instances, rather than using separate objects, elements, or interactions.
[38/S3/F3] External or environmental consistency in system design means that the elements and interactions in a virtual world should closely match the user's real-world experience and knowledge, so that real-world knowledge transfers to the virtual world as closely as possible.
[38/S3/F4] Shneiderman's second golden rule is to design for universal usability, meaning a system should provide facilities for all user categories and support different user categories rather than only specific user categories.
[38/S3/F5] Menu-based options can be preferable to hotkey options for users who may not remember hotkey combinations because menu options rely on recognition rather than recall, and recall is a skilled task, whereas hotkeys such as Control plus S (Ctrl+S) are faster for users who do not want to use slower menu-based options.
[38/S4/F0] The third rule of usable design is to provide informative feedback to users for whatever action the user performs.
[38/S4/F1] A progress bar is informative feedback that sometimes appears during a task, shows the percentage of the task completed, and gives the user a sense of how much longer to wait; without it, the user cannot tell what the system is doing or how much of the task is completed.
[38/S4/F2] A color change on a save icon after a save operation is informative feedback that indicates the save operation is done successfully; without it, the user cannot tell whether the save operation worked.
[38/S4/F3] The fourth rule is to design dialogues to yield closure by organizing task execution into beginning, middle, and end parts and providing feedback at the end of each group, so the user feels the task is started, executed, and completed.
[38/S5/F0] The fifth rule in system design is to offer error prevention and simple error handling.
[38/S5/F1] In system design, user errors cannot be completely eliminated, so a design should aim to keep error rates low; for example, close and start options for the same interface should not be placed side by side because a user may accidentally choose the wrong action.
[38/S5/F2] In system design, when an error occurs, error handling should give simple, easy-to-understand information rather than complicated error messages, because complicated messages can confuse and scare the user.
[38/S5/F3] The sixth rule in system design is to permit easy reversal of actions, ideally by keeping a reversal option available so users can return from an erroneous situation.
[38/S5/F4] Undo and redo facilities are primarily meant to permit easy reversal of actions.
[38/S6/F0] The seventh usability rule, keeping users in control, requires that lay users feel in control of the system, perceive that their interaction changes the system state, and receive feedback on their actions and results, because lack of this feeling makes them feel at a loss and reduces usability.
[38/S6/F1] In a broad sense, human memory comprises short-term and long-term memory, where short-term memory is a note-like non-permanent store used to bring information from long-term memory to aid day-to-day activities.
[38/S6/F2] George Miller's 1956 psychological finding, the seven plus or minus two rule, gives the short-term memory limit as five to nine chunks of information at a time, so holding fewer underutilizes short-term memory and holding more overutilizes it and is harmful.
[38/S6/F3] The last usability rule, reducing short-term memory load, requires keeping the information needed to operate an interface or perform an interaction between five and nine chunks for the user's optimum outcome, and not forcing users to remember more than nine chunks.
[38/S6/F4] A chunk of information is a unit of information that can be one letter, one word, a whole sentence, or a whole concept, depending on the application.
[38/S6/F5] The eight generic usability rules are not specific to a particular product or system, and they can be analyzed for applicability to a broad class of interactive systems, including extended reality systems.
[38/S7/F0] Interaction in non-immersive settings, such as augmented reality (AR), is similar to familiar interactions such as touch and gesture.
[38/S7/F1] For immersive virtual reality (VR) or mixed reality (MR) experiences, specialized techniques and setups are used, and suitable interaction techniques should be known and used to design the experience properly and enhance presence.
[38/S7/F2] Interaction in immersive environments is broadly categorized into object interaction, navigation, and interaction for system control, where object interaction means selection and manipulation of objects that are part of the virtual environment, navigation means moving from one point to another in the virtual environment, and interaction for system control means interaction required to change system-related settings.
