[62/S0/F0] In the Unity development environment, built-in support gives a good-quality experience that is only what the system provides, so to obtain a more customized experience according to the programmer's expectations and needs, the programmer must write scripts or small pieces of code to change the built-in support.
[62/S0/F1] Unity's scripting environment is set up automatically when the Unity package is installed, Unity supports integrated development environments (IDEs) such as Visual Studio, Visual Studio Code, and JetBrains Rider, and on Windows and Mac the default Unity installation also installs Visual Studio, which can be used to develop and compile scripts.
[62/S0/F2] The scripting language supported by Unity is C#, which is an object-oriented programming language created by Microsoft.
[62/S0/F3] In Unity, a C# script can be attached as a component to a game object to control the behavior or activities of that object, and creating a C# script is essentially creating a new type of component that can be attached to game objects, providing a component that behaves as desired rather than according to the built-in support provided by the environment.
[62/S0/F4] Once a C# script is attached as a component to a game object in Unity as part of the design or development, it starts working whenever the game is executed, and it allows the developer to trigger game events, modify component properties over time, and respond to user input in any way the developer wants.
[62/S0/F5] Unlike most other assets, C# scripts in Unity are usually created directly within Unity, using the interface provided by the integrated development environment (IDE), by choosing Assets, then Create, then C# Script from the main menu, and the new script is created in the folder selected in the project panel when the project is started.
[62/S1/F0] A Unity C-sharp (C#) script file begins with a namespace component, with using statements such as using Unity engine and using system.collections, and defines a public class, typically inherited from MonoBehaviour, whose name is the same as the file name.
[62/S1/F1] A Unity script contains a Start function that is called whenever the script is called, as the starting point, and an Update function that is called in each frame and is invoked whenever the script executes and some change happens.
[62/S1/F2] In a Unity script, the Vector3 data type represents the position of a three-dimensional (3D) point by storing three coordinates as three elements of a vector.
[62/S1/F3] In Unity, a developer can see the code in a script file by double-clicking the script asset and can check variable values in the Inspector interface on the Unity Hub editor.
[62/S1/F4] In a Unity script, the Debug.Log function prints a message to the console output, which can be seen after running the game or application or after the script has been executed.
[62/S2/F0] In Unity's scripting environment, the Destroy function, which comes under the MonoBehaviour class, destroys a game object from the scene after a specified delay, typically in seconds; for example, Destroy(gameObject, 5f) makes the game object no longer visible in the scene five seconds after the function is called.
[62/S2/F1] Unity scripts use prebuilt functions that are critical for making a script work, and user-defined functions, which are defined by the user and are typically part of a good script.
[62/S2/F2] An event function in Unity is a function that Unity activates in response to an event that occurs during gameplay, and when the event happens, Unity passes control to the event function, its body executes, and then control is passed back to Unity.
[62/S2/F3] Common Unity gameplay events and their event functions include regular update events, such as the Update, FixedUpdate, and LateUpdate functions; initialization events, such as the Start and Awake functions; graphical user interface (GUI) events, such as the OnGUI, OnMouseOver, and OnMouseDown functions; physics events, such as the OnCollisionEnter, OnCollisionStay, and OnCollisionExit functions, which relate to contact being made or broken; and other physics-related events, such as the OnTriggerEnter, OnTriggerStay, and OnTriggerExit functions, which are called when a collider is configured as a trigger.
[62/S2/F4] Unity's event functions can be used to impose realistic behavior, such as physical behavior in physics-event functions and interactive behavior in graphical user interface (GUI) event functions.
[62/S3/F0] To instantiate a prefab at runtime, the script being written needs a reference to that prefab.
[62/S3/F1] In the editor interface, a prefab is attached for runtime instantiation by creating a new script, creating an empty game object, adding the script to the game object as a component, creating a prefab, and dragging that prefab from the project window into the script component's My Prefab field.
[62/S3/F2] The scripting environment supports standard conditional if-else statements.
[62/S3/F3] Loops in the scripting environment can be entry-controlled or exit-controlled: for and while loops are entry-controlled because the loop condition is checked before the loop body executes, and a do-while loop is exit-controlled because the loop body executes at least once and the condition is checked after the loop body executes.
[62/S3/F4] A for each (foreach) loop can be used for arrays or collections of homogeneous data types, allowing the programmer to work with the collection directly instead of dealing with individual data types.
[62/S4/F0] The transform property attached to every game object in a scene stores the object's position, rotation, and scale, and it can be modified programmatically through a script, for example in the update function by using transform.Translate, rotation values, and local scale values, to make the object behave as desired.
[62/S4/F1] A coroutine in Unity is a method that allows a developer to spread tasks across several frames by pausing execution, returning control to Unity, and continuing where it left off on the following frame.
[62/S4/F2] Coroutines are not threads and are not designed to behave like threads; synchronous operations within a coroutine still execute on the main thread, and coroutine execution does not spawn individual threads.
[62/S4/F3] A gradual opacity fade of an object is visible only when its alpha or opacity value is reduced over a sequence of frames so that Unity renders the intermediate values; a fade function called only once is not perceivable, so the fade must be defined as a coroutine and started so that the change is spread frame by frame.
[62/S4/F4] InvokeRepeating invokes a method after a specified initial delay and then repeatedly at a specified interval; it takes a function name and two times in seconds, the first for the initial start time and the second for the repeat interval.
[62/S5/F0] In Unity, scripting supports user interaction with input devices through inbuilt handling of inputs such as the mouse, keyboard, and buttons; for other device-specific inputs, imported software development kit (SDK) input support may be needed and it extends Unity's inbuilt support.
[62/S5/F1] In the Unity development environment, after the script is written and the system is built, the last stage is to publish or deploy the system, and the editor's Build Settings window, reached by going to File Build Settings, contains all settings and options to publish the build.
[62/S5/F2] In the Unity development environment's editor, the Build Settings window's Scenes in Build panel manages which scenes are included in the build, its platform section selects the platform to which the system is deployed, and the Build or Build and Run button begins the build process.
[62/S6/F0] If a system is to be deployed on a specified hardware platform, head-mounted display (HMD), or smart glasses, and that platform provides features or functions not included in the built-in support provided by the Unity environment, the developer imports software development kits (SDKs) or packages to access and use those platform-specific functions.
[62/S6/F1] In the Unity layered architecture, the application is the top layer, and the software development kit (SDK) layer, which is positioned on top of the Unity layer, is treated as part of the installed Unity package whose application programming interfaces (APIs) are used.

[62/S6/F3] Unity's built-in support for object recognition or computer vision operations, such as object detection, recognition, and tracking, is not extensive and not very good, so seamless and efficient performance of these operations requires external packages.
[62/S6/F4] The basic steps for integrating a software development kit (SDK) into the Unity development environment are to install Unity Hub, import the SDK package into the Unity environment, use the functions of both Unity and the SDK, and then compile, build, and deploy.
[62/S7/F0] Vuforia is a software development kit (SDK) specifically developed for augmented reality (AR) that supports advanced computer vision functionality for recognizing images and objects and interacting with spaces in the real world.
[62/S7/F1] Vuforia is a cross-platform software development kit (SDK) that supports multiple platforms, including Unity, Android, and iOS, and using it requires a license, with a developer's license available.
[62/S7/F2] To install Vuforia in Unity, a new Unity project is created using the universal 3D template or an empty project, and the Vuforia engine is added to the project assets either by downloading the Vuforia SDK for Unity from developer.vuforia.com or by manually importing the package as a custom package, after which it can be used directly in the Unity editor.
[62/S7/F3] The Vuforia configuration requires a Vuforia account and license, and the license is added to the Unity project from that Vuforia account.
[62/S7/F4] Vuforia setup requires creating a new database on the Vuforia website, adding the images or markers to be tracked to that database so the Vuforia engine can recognize them, and downloading the database package file and importing it into the project as a custom package because the database is required for recognition.
[62/S7/F5] In the Unity sample scene, the main camera is removed, the Vuforia augmented reality (AR) camera and image target are selected, image targets and models folders are created in assets, the target image is placed in the image targets folder, a three-dimensional (3D) model downloaded from sketchfab.com is placed in the models folder, the target image asset is assigned to the image target component, the 3D model is assigned to the image target component in the sample scene, and the 3D model is scaled to the desired dimensions in the inspector.
[62/S7/F6] An image target behavior script is attached to or used to modify the behavior of a Vuforia image target, and it performs the operations after the Vuforia engine recognizes the marker.
[62/S7/F7] For this sample project, the Unity player settings are configured under Edit > Project Settings > Player > Other by removing Vulkan and adding the Open Graphics Library (OpenGL) application programming interface (API), unchecking AutoGraphics API, unchecking Advanced RISC Machines (ARM) version 7, checking ARM 64, using the IL2CPP scripting backend, and ensuring the minimum API level is greater than 7; these settings are application-specific and may not work for other projects or platforms.
[62/S7/F8] For the Android platform, the build is created by following File > Build Settings > Android > Switch Platform, connecting the Android device through a universal serial bus (USB) cable with USB debugging enabled, and selecting Build and Run, which creates an Android package (APK) file and deploys it directly to the device; alternatively, the Android package (APK) file can be developed first and then transferred and installed separately.
[62/S7/F9] In the sample marker-based augmented reality (AR) application, the Earth image is the marker, and when a device running the Android package (APK) file captures a matching colored image on a mobile screen, desk, or paper, the Vuforia engine recognizes the marker and displays a three-dimensional (3D) model in place of the marker; the displayed image must match the original image in color, shape, and size.
