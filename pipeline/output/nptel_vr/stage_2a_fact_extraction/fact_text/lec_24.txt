[24/S0/F0] Empirical or field studies of user behavior are typically needed to understand who the users of an interactive system are and how they behave, but they are time-consuming, laborious, and require elaborate setup and planning, so interactive-system designers can rely on the novice, intermittent, and expert user categorization instead of always starting with field studies.
[24/S0/F1] A three-class classification of interactive-system users consists of novice users, who use the system for the first time, intermittent users, who use it occasionally, and expert users, who use it regularly over a long period of time.
[24/S0/F2] In the novice, intermittent, and expert user categorization, an expert user is not a technology expert but a person who is an expert in using the system and can use it efficiently.
[24/S0/F3] The novice, intermittent, and expert user classes provide a starting point for understanding users and making interactive-system design decisions when designers assume their potential users belong to one of these classes, because users in different classes are likely to behave differently and designers can broadly understand the behavior of each class.
[24/S0/F4] A word processing or similar processing application can provide multiple options, such as a hotkey combination and a menu option, for the same task to cater to different user groups.
[24/S0/F5] For saving a file, the menu option takes longer than the hotkey combination but is suitable for novice first-time users because remembering hotkey combinations is generally difficult for them, while the hotkey combination may be a better alternative for intermittent users and is always preferable for expert users.
[24/S0/F6] The novice, intermittent, and expert categorization is only one broad way of classifying users; more fine-grained categorizations are possible, and better categorizations can be based on empirical studies of users, but the broad novice, intermittent, and expert categorization is useful when the design process starts.
[24/S1/F0] The meaning of user-centric design varies by stakeholder, particularly by designer role: for a user interface or user experience designer it primarily concerns the design of interface elements and layouts, which is mostly a creative design aspect informed by user characteristics; for an industrial product designer it concerns the form of the product, namely its shape, size, and look; and for an electronic engineer it concerns hardware-level features, such as more sensors, smaller chips to reduce size, and a more power-efficient battery.
[24/S1/F1] An application software developer building software such as a virtual reality (VR) or augmented reality (AR) system incorporates user characteristics by following a development or design lifecycle that accounts for users' characteristics, needs, and expectations so that the system is easier for the user to use and better matches the users' needs and expectations.
[24/S2/F0] Usability is an explicit measure of how good a system is from the point of view of the user.
[24/S2/F1] The International Standards Organization (ISO) 9241-210-2009 standard defines usability as the extent to which a product can be used by specified users to achieve specified goals with effectiveness, efficiency, and satisfaction in a specified context of use.
[24/S2/F2] The three crucial aspects of the International Standards Organization (ISO) 9241-210-2009 usability definition are that a usable product is intended for a specified group of users rather than everybody, that it supports a specified set of goals rather than every conceivable feature, and that it is designed for a specified context of use rather than all usage scenarios.
[24/S2/F3] The three measures of usability are effectiveness, efficiency, and satisfaction; effectiveness is whether the user can do what they want to do, efficiency is how fast the user can do what they want to do, and satisfaction is how satisfied the user is when using the system.
[24/S3/F0] User-centered design is a design that results from applying a user-centric approach, and it involves users actively or passively in the design or development lifecycle used to build a usable software application.
[24/S3/F1] Ben Shneiderman coined the term user-centered design in 1986 in the context of graphical user interfaces.
[24/S3/F2] The objective of user-centered design is to design products that increase usability.
[24/S3/F3] Cooperative design (coined by Greenbaum and Kyng in 1992), participatory design (Schuler and Namioka, 1993), contextual design (Beyer and Holtzblatt, 1997), and human-centered design (the standard term preferred by the International Organization for Standardization (ISO) rather than user-centered design) are related terms that are more or less similar in concept to user-centered design and refer to taking users into the design process.
[24/S3/F4] In user-centric software design and software development, the core design concern is the design of usable systems that cater to the needs and expectations of lay persons or layman users.
[24/S4/F0] The user-centered software development approach requires that users be actively or passively involved in the overall software development lifecycle chosen to build a system.
[24/S4/F1] Extended Reality (XR) systems are highly interactive like other interactive systems, and consideration of human factors is important to understand how easily a user can provide input and perceive output.
[24/S4/F2] The core concern of Extended Reality (XR) software is to create a relationship between the user and the virtual environment, and both software and hardware play important roles in building that relationship.
[24/S4/F3] An Extended Reality (XR) system comprises hardware, the middleware that is the XR engine, and the application layer.
[24/S4/F4] In an Extended Reality (XR) system, the user's actions and positions are tracked by input devices and sent as input data; the input data is processed and the environment is rendered; the XR engine, as middleware, uses hardware resources to generate output data; and output devices stimulate the user's senses with that output.
[24/S4/F5] In an Extended Reality (XR) system, interaction design and modeling of user input should follow a user-centered design approach so that the user can provide input data seamlessly, effectively, and easily.
[24/S4/F6] In an Extended Reality (XR) system, perceptual design and modeling of output requires a user-centered design approach because it is crucial to ensure that generated output stimuli match the user's perception of them, so that the user can perceive and understand the output easily.
