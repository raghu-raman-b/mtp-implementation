[58/S0/F0] Rendering is the most challenging part of immersive experience generation from the point of view of the system.
[58/S0/F1] The three-dimensional (3D) graphics pipeline has five stages, and the first four stages are object representation in the local coordinate system; modeling or geometric transformation from the local coordinate system to the world coordinate system; lighting in the world coordinate system; and viewing transformation from the world coordinate system to the three-dimensional (3D) view coordinate system.
[58/S0/F2] In the three-dimensional (3D) graphics pipeline, after the viewing transformation, the view pipeline includes clipping in the three-dimensional (3D) view coordinate system, hidden surface removal in the three-dimensional (3D) view coordinate system, projection transformation from the three-dimensional (3D) view coordinate system to the two-dimensional (2D) view coordinate system, and window-to-viewport transformation from the two-dimensional (2D) view coordinate system to the device coordinate system.
[58/S0/F3] The fifth stage of the three-dimensional (3D) graphics pipeline is the scan conversion stage, also called the rendering stage, which transforms a device coordinate description into a screen coordinate description on the pixel grid.
[58/S1/F0] The device coordinate system used to define the two-dimensional (2D) viewport is a continuous coordinate system, so its coordinate values can be any real number.
[58/S1/F1] A display device uses a pixel grid to render an image, and points on that pixel grid can only have integer coordinates.
[58/S1/F2] Scan conversion, also called rendering or rasterization, is, after the earlier four stages, the fifth stage in which mapping algorithms transform continuous two-dimensional (2D) viewport coordinates into a discrete pixel-grid coordinate system by choosing the nearest integer-coordinate pixels, so a line is rendered by coloring specific pixels.
[58/S2/F0] In point rendering, a point represented by real-number coordinates is mapped to the nearest integer coordinate values, which maps from device space to discrete space; this rounding method is suitable for points but not for other geometric shapes such as lines and circles.
[58/S2/F1] A naive line-rendering method requires many floating-point operations, and because floating-point operations slow down a computer, the objective of efficient line-rendering algorithms is to avoid floating-point operations.
[58/S2/F2] Bresenham's line-drawing algorithm is a popular line-rendering algorithm that identifies the pixels that approximately represent a line without using floating-point operations.
[58/S2/F3] The Bresenham line-drawing algorithm is described for line slopes between -1 and +1, with minor modification needed for other slopes; its input is the two line endpoints and its output is the set of pixels that approximate the line segment.
[58/S2/F4] In Bresenham's line-drawing algorithm for line slopes between -1 and +1, the algorithm first computes delta x, the difference between the two endpoints' x coordinates, delta y, the difference between their y coordinates, and the decision parameter p, defined as twice delta y minus delta x; it initializes x and y to the first endpoint's x and y coordinates and adds that pixel to the output pixel set; then, in a loop until the other endpoint is reached, if p is less than 0 it increments x by 1 and resets p to the older p plus twice delta y, otherwise increments x and y by 1 and resets p to the older p plus twice delta y minus twice delta x, adding each computed coordinate to the output pixel set.
[58/S2/F5] Bresenham's line-drawing algorithm is efficient and speeds up line rendering because it uses integer arithmetic, such as addition and multiplication, and avoids floating-point operations such as rounding, division, and sometimes floating-point multiplication.
[58/S2/F6] Speeding up line rendering makes the system more efficient because at any instant a system may need to render a large number of line segments, and in interactive graphics such as virtual reality each user input can change the scene and require redrawing hundreds of thousands of lines.
[58/S2/F7] Similar efficient rendering algorithms exist for other geometric shapes, such as circles, ellipses, filled areas, and polygons, and they are more complex than line rendering.
[58/S2/F8] The basic idea for rendering a shape on a screen is to map the original shape to the set of pixels that represent it as fast as possible by reducing floating-point operations.
[58/S2/F9] For lines, floating-point operations can be completely eliminated, whereas for other shapes they may not be completely eliminated but can be minimized.
[58/S3/F0] Aliasing is distortion that may occur in an original shape after scan conversion because scan conversion renders pixels that are close to points on the original shape rather than exactly rendering the points, so an approximated line may not exactly match the original line.
[58/S3/F1] If aliasing is left unaddressed, it may lead to distortion that is visible with a change in resolution and that will reduce the quality of experience.
[58/S3/F2] Anti-aliasing operations are additional operations, using complex algorithms, that remove or reduce the distortion caused by aliasing so that the end effect is better.
[58/S3/F3] Anti-aliasing is essential and adds further computation to the overall computation of pixel intensities along with the other rendering stages.
[58/S3/F4] In virtual reality (VR), a realistic experience with rich realistic content, a dynamic scene that changes with user input, a high degree of interaction, motion achieved through animation or video, and the fact that a simple lighting model may not be a good option increase the computational complexity of rendering manifold.
[58/S3/F5] The challenge in virtual reality (VR) rendering is to handle a computationally complex rendering process without the user perceiving lag or distortion.
[58/S4/F0] A computer graphics (CG) programmer does not always need to implement the stages of a graphics pipeline from scratch; instead, the programmer can import graphics libraries and use the application programming interfaces (APIs) provided by those libraries to deal with the lower-level tasks, choosing a library whose APIs suit the requirements.
[58/S4/F1] Examples of graphics libraries include OpenGL, which stands for Open Graphics Library, Vulkan, and Direct3D.
[58/S4/F2] The application programming interfaces (APIs) provided by graphics libraries are predefined sets of functions that, when invoked with appropriate arguments or parameters, perform specific tasks.
[58/S4/F3] The application programming interfaces (APIs) provided by graphics libraries eliminate the need for a programmer to know every detail of the underlying system or platform, such as processor details, memory details, and operating system details, in order to build a graphics application.
[58/S5/F0] A layered virtual reality (VR) software architecture consists, from top to bottom, of the VR application layer, the software development kit (SDK) layer, the VR engine or game engine layer, the native rendering library layer with libraries such as OpenGL, Vulkan and Direct3D, the operating system layer, and the hardware layer including the graphics processing unit (GPU); the application layer calls the SDK layer, the SDK layer calls the VR engine layer, the VR engine calls the application programming interfaces (APIs) of the native rendering libraries to perform rendering, the native rendering libraries sit on top of the operating system layer, and the operating system layer sits on top of the hardware layer.
[58/S5/F1] In a layered virtual reality (VR) system, a developer can rely on the software development kit (SDK) layer to access the VR engine; the developer has to install the VR engine and import the SDK within the engine, and the VR engine's job is to let the developer deal with graphics through the application programming interfaces (APIs) provided by the native rendering libraries without directly accessing those native rendering libraries.
[58/S6/F0] A graphics processing unit (GPU) is the processing unit of a separate graphics card, with its own memory elements, that is used in computer graphics and virtual reality to exploit the inherent parallelism of graphics operations, which are highly parallel, whereas central processing units (CPUs) are generally not designed for large-scale parallel activities, although modern CPUs have some parallel features.
[58/S6/F1] A GPU is typically a multicore system in which many cores, each capable only of simple integer and floating-point arithmetic, work simultaneously on one single instruction and produce data simultaneously, and groups of cores form streaming multiprocessor units, each containing several cores.
[58/S6/F2] A GPU is broadly organized with a host, input assemblers and a thread execution manager, where the manager allocates work to many streaming multiprocessors, each of which has a parallel data cache, and a texture storage stores predefined surface colors, with the elements exchanging data with global memory through load and store information.
[58/S6/F3] The GPU performs modeling transformation by applying transformations such as rotation, multiplying the same transformation matrix with each vertex vector simultaneously for all vertices, producing a stream of transformed triangles from local coordinates to world coordinates, which gives a significant performance gain in real-time rendering because millions of vertices need to be processed per second and even more for a realistic immersive experience.
[58/S6/F4] Most graphics systems assume that a scene to be rendered is made of triangles, so surfaces are converted into triangular meshes regardless of how a developer defines an object, and the GPU assumes such a mesh as input.
[58/S6/F5] Graphics libraries provide application programming interfaces (APIs) through which triangles in a mesh are sent to the GPU one vertex at a time, and the GPU assembles the vertices into triangles.
[58/S6/F6] The GPU computes vertex color by performing vector dot products, as in the simple lighting model, simultaneously for multiple vertices.
[58/S6/F7] The GPU projection stage combines viewing transformation, projection transformation and viewport transformation in a composite matrix multiplied with vertices, producing a stream of triangles in screen or device coordinates, a continuous coordinate space, ready to be converted to pixels.
[58/S6/F8] In rasterization, the pixels overlapped by device-space triangles are determined, and algorithms exploit the fact that each pixel can be treated independently from all other pixels so that the colors of all pixels can be determined simultaneously in parallel.
[58/S6/F9] In the GPU pixel processing stage, the two activities that take place are surface texturing and hidden surface removal.
[58/S6/F10] In the pixel processing stage, the simplest surface texturing method applies stored texture images to the geometry being rendered by replacing the computed pixel color with the texture color at the corresponding texture point; GPUs store textures in high-speed texture storage on the graphics card, which each pixel calculation must access, and because nearby pixels tend to access nearby texture image locations, specialized memory caches reduce access time.
[58/S6/F11] In the pixel processing stage, hidden surface removal uses a depth buffer algorithm in which a dedicated depth buffer stores the depth information for points in a three-dimensional (3D) scene before projection onto a two-dimensional (2D) plane, where depth is the viewer's distance with respect to each pixel.
