[22/S0/F0] Non-flash-based browser tools for augmented reality (AR) rapid prototyping can avoid third-party browser plugins by letting a developer with mastery of HyperText Markup Language (HTML), Web Graphics Library (WebGL), or similar web component technologies write their own code to create a fast prototype.
[22/S0/F1] Open Frameworks is an open-source C++ middleware framework and library that is a non-web-based authoring tool for desktop and mobile platforms, combining multiple libraries.
[22/S0/F2] For augmented reality (AR) application development, Open Frameworks provides support for tracking, rendering, and interaction, and can combine more than two libraries, for example a tracking library such as augmented reality (AR) Toolkit for hand tracking, a three-dimensional (3D) scene graph for rendering, and audio playback libraries, to generate different effects.
[22/S0/F3] Wikitude is a free augmented reality (AR) browser application that runs on mobile devices as a useful mobile prototyping tool.
[22/S0/F4] Wikitude treats the mobile device primarily as a client or rendering device only, and the application connects to backend servers for content and specification of user interface elements, with computation not taking place on the mobile device but possibly taking place on the backend server.
[22/S0/F5] Wikitude makes prototyping easier or faster when developers have their own content; without content, developers depend on default content provided by the tool, which may reduce flexibility but is still usable.
[22/S1/F0] Plugins to existing tools are a category of augmented reality (AR) software in which a plugin is added to an existing interactive two-dimensional (2D) or three-dimensional (3D) content authoring tool that may not itself support AR content or system development, and the plugin adds AR-specific functions such as tracking, visualization, and 3D registration of digital content over the real-world view, while relying on the main authoring tool for content authoring.
[22/S1/F1] Plugins to existing tools provide an easy and quick method for developing augmented reality (AR) applications when the developer already knows the host authoring tool, because the developer can rely on knowledge of the original tool and only needs to understand the plugin, reducing the required understanding of the system; if the developer does not know the authoring tool, the approach makes no sense because everything must be learned from scratch.
[22/S1/F2] Many interactive three-dimensional (3D) graphics authoring tools, including Unity, Vizard, and Lumion, are used to create interactive 3D applications, and most of these tools have plugins for augmented reality (AR) visualization; Unity has the widest range of available solutions for AR visualization.
[22/S1/F3] The augmented reality (AR) Toolkit for Unity from the AR Tool Works is an example of an AR plugin for Unity that provides marker-based tracking, image-based or computer-vision-based tracking, and AR visualization support.
[22/S1/F4] Vuforia is a tracking library that has an augmented reality (AR) plugin that works with Unity three-dimensional (3D) and can be used to create AR applications, particularly mobile AR applications for iOS and Android platforms.
[22/S1/F5] Limitations of using plugins to add augmented reality (AR) support to existing content authoring tools are that user interface and interaction design can be limited to what the underlying authoring tool provides, software and hardware configuration depends on that tool, and content produced with the authoring tool usually becomes dependent on proprietary player software in most cases.
[22/S1/F6] A way to resolve the limitations of higher-level augmented reality (AR) tools or plugins is to use low-level software development tools, such as software libraries, and build the system from scratch rather than depending on a third-party tool, an approach that applies to any higher-level tool.
[22/S2/F0] Standalone authoring tools are applications that allow users to create augmented reality (AR) experiences without programming experience.
[22/S2/F1] Unlike plugins, which require a basic software or basic authoring tool on which augmented reality (AR) support is provided through a plugin, standalone authoring tools are complete packages that include content authoring and augmented reality support and do not require or depend on any other tool.
[22/S2/F2] Standalone augmented reality (AR) authoring tools typically support scene construction, animation, and adding interactive behavior, with capabilities ranging from scene construction only to the full capability of building complex interactive behavior.
[22/S2/F3] Most standalone augmented reality (AR) authoring tools provide drag-and-drop graphical user interfaces (GUIs) that allow developers to create applications or experiences without coding, so users with basic personal computer (PC) skills and non-programmers can learn and use them.
[22/S2/F4] Standalone augmented reality (AR) authoring tools can provide scripting-language support for developers who know scripting languages, and applications built with absolute zero coding have limited utility compared with advanced systems that use scripting support for more flexibility.
[22/S2/F5] Wikitude Studio is an example of a standalone augmented reality (AR) authoring tool; it is a web-based package that allowed users to create rich mobile augmented reality content and deploy it either to the Wikitude augmented reality browser app or as a custom mobile app, and it supported various media, including three-dimensional (3D) models and animations registered to the real world.
[22/S3/F0] Augmented reality (AR) software tools and packages are available in four categories based on the programming skill required: low-level libraries and frameworks, which require the highest programming skill; standalone authoring tools, which require the least programming skill; and, between these extremes, rapid prototyping tools and plugins to existing systems.
