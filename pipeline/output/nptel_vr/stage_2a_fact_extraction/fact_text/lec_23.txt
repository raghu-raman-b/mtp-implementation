[23/S0/F0] Extended reality systems belong to the broad class of systems called interactive systems.
[23/S0/F1] Mark Weiser's 1991 paper 'The Computer for the 21st Century', published in Scientific American, stated that the most profound technologies are those that disappear.
[23/S0/F2] The statement that the most profound technologies are those that disappear means that a very advanced technology should ideally not be visible to the user, and the user should feel like dealing with any other item rather than a specialized technological item.
[23/S0/F3] Mark Weiser's quote that the most profound technologies are those that disappear and presence refer to the same thing: the technological aspect surrounding the user should disappear from the user's perception, and the goal is to build systems that do not make it apparent that the user is using a specialized technological product.
[23/S0/F4] The earliest computers occupied huge rooms with many wires, programming referred to the idea of reconnecting the wires, and they were accessible only to a very few select people.
[23/S0/F5] In the development of computer systems, people have tried to make technology disappear from the user's point of view, and the current stage defined by popular technological products such as wearable devices, mobile devices, flexible devices, and connected devices is referred to as Internet of Things (IoT) or ubiquitous computing, in which users are surrounded by multiple connected computers that can communicate with each other without the user separately operating them, moving toward making technology disappear.
[23/S1/F0] Interactive computing systems, or interactive systems, are systems in which interaction takes place between the computer or system and the user.
[23/S1/F1] In interactive systems, the user is a lay person or layman user who is not necessarily a technology expert and who wants to use the system rather than understand how the system works.
[23/S1/F2] Technical terms in a system error message, such as event log, security accounts manager, and safe mode, should not be expected to be understood or acted upon by a lay end user, and a hexadecimal status code in such a message is generally incomprehensible to a layperson.
[23/S1/F3] An error message couched in technical jargon that a layperson is likely to fail to understand can make the user anxious, leave the user not knowing what is wrong or how to get out of it, and may lead to the user refraining from using the system further and to a loss of motivation for further use.
[23/S1/F4] Designers of interactive systems that are intended to be used by laypersons should not force users to learn the underlying technology or understand the relevant technical terms.
[23/S2/F0] The user-centric approach, generally recommended for building interactive systems, is the process of designing computer systems in which users' needs and expectations are taken care of by considering user characteristics, and it starts by understanding user characteristics, what users need and expect, and then designing the system based on that.
[23/S2/F1] The key characteristics of a user-centric approach are designing interface elements that are acceptable to users, designing layouts that organize elements on the screen or interface to meet user expectations, helping users perceive the system state from their point of view rather than from technical details, and designing interactions that fulfill users' needs by taking them to desired system states, allowing users to get work done by easily transitioning from one state to a goal state.
[23/S3/F0] Human-computer interaction (HCI) is a discipline concerned with the design, evaluation, and implementation of interactive computing systems for human use and with the study of major phenomena surrounding interactive computing systems.
[23/S3/F1] ACM SIGCHI is the official body that deals with human-computer interaction (HCI) and provides the definition of HCI.
[23/S3/F2] The core concern of human-computer interaction (HCI) is incorporating humans into the design, which requires first understanding users and then incorporating user characteristics into the design.
[23/S4/F0] Human factors in system design requires designers to know the users' characteristics and design the system accordingly, because users who perform the same broad task, such as a traveler or agent and a database administrator obtaining railway ticket information, can have different expectations, needs, and query-language skills, and therefore require different interfaces for providing input, seeing the outcome, and acting on the outcome.
